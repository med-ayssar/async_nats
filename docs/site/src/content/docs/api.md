Include `<AsyncNats.h>` for `co_main` and `onError`, `<AsyncNats/client.h>` for the client API, and `<AsyncNats/core/Core.h>` for the runtime. The library defines `main`; the application defines `co_main`.

The same declarations are generated by Doxygen. Open the [Doxygen reference](/doxygen/index.html) or the [function index](/doxygen/functions.html). Each section below links to its generated page.

## Entry point

Doxygen: [`AsyncNats.h`](/doxygen/_async_nats_8h.html), which declares `co_main`.

### `co_main`

```cpp
auto co_main(int argc, char** argv) -> AsyncNats::Main;
```

The application defines this. `Main` is `boost::cobalt::task<int>`. The library calls it from `main` after the runtime is running. The returned integer is logged as `co_main returned N`. The process exits 0 unless an exception escapes. Register `onError` before the first `co_await`.

### `main`

```cpp
auto main(int argc, char* argv[]) -> int;
```

Defined by the library in `src/AsyncNats/core/Main.cpp`. It constructs `EventLoop`, calls `setup()`, then `run()`. An application does not define `main`.

## Connection

Doxygen: [`AsyncNats`](/doxygen/namespace_async_nats.html) and [`Client`](/doxygen/class_async_nats_1_1_client.html).

### `connect`

```cpp
auto connect(std::string url) -> boost::cobalt::task<Client>;
```

Open `nats://host:port`. The port defaults to 4222. Resolves the host, connects, reads `INFO`, and sends `CONNECT` and `PING`. After `PONG` the read loop owns the socket. A stop request during connect closes the new socket and throws kind `signal`. Kind `unreachable` means resolve or TCP connect failed. Kind `interrupted` means the handshake failed.

### `onError`

```cpp
void onError(ErrorHandler handler);
```

Register the process-wide handler. `ErrorHandler` is `task<void>(Error)`. Call this before the first `co_await` in `co_main`. Kind `closed` does not run the handler. A handler that is already on the stack is not entered again. An empty handler clears the previous one. A throw from the handler is logged as `nats error handler failed`.

### `Client::publish`

```cpp
auto publish(std::string subject, std::string payload) -> boost::cobalt::task<void>;
```

Publish `payload` to `subject`. Throws when the client is empty, the subject is invalid, or the write fails.

### `Client::subscribe`

```cpp
auto subscribe(std::string subject) -> boost::cobalt::task<Subscription>;
```

Subscribe and return a pull handle. `Subscription::next` waits for one message. Throws when the client is empty, the subject is invalid, or the write fails.

```cpp
auto subscribe(std::vector<Route> routes) -> boost::cobalt::task<void>;
```

Subscribe each route and start its handler for every message. Sends one `SUB` per route and returns when those frames are written. It does not wait for a message. An empty list does nothing. Duplicate subjects become separate subscriptions. If the write fails, the routes just added are dropped. Throws when the client is empty, a subject or handler is invalid, or the write fails.

### `Client::unsubscribe`

```cpp
auto unsubscribe(std::vector<std::string> subjects) -> boost::cobalt::task<void>;
```

Send `UNSUB` for every route on these subjects and drop the handlers. Unknown subjects are skipped. An empty list does nothing.

### `Client::request`

```cpp
auto request(std::string subject, std::string payload) -> boost::cobalt::task<std::string>;
```

Publish `payload` and return the body of the reply. Subscribes a one-shot inbox, publishes with that inbox as the reply subject, and waits for one response.

```cpp
auto request(std::string subject, std::string payload,
             std::vector<std::pair<std::string, std::string>> headers)
    -> boost::cobalt::task<std::string>;
```

The same call with NATS headers. Each pair is a header name and its value.

### `Client::close`

```cpp
auto close() -> boost::cobalt::task<void>;
```

Shut the socket down and wake waiters with kind `closed`. Does not log and does not run `onError`. An empty client returns immediately.

### `Client::closed`

```cpp
auto closed() -> boost::cobalt::task<void>;
```

Suspend until the connection fails or `close()` runs, then throw. The thrown `Error` carries the first reason that ended the connection. A later failure does not replace that reason. This call does not close the client.

## Subscription

Doxygen: [`Subscription`](/doxygen/class_async_nats_1_1_subscription.html).

### `Subscription::next`

```cpp
auto next() -> boost::cobalt::task<Message>;
```

The next message for this subscription. Returns immediately when a message is already queued. Otherwise it suspends until a message arrives, the connection fails, or `unsubscribe()` runs. The per-subscription queue has no limit. Throws when the connection failed or this subscription is closed.

### `Subscription::unsubscribe`

```cpp
auto unsubscribe() -> boost::cobalt::task<void>;
```

Send `UNSUB` and drop this subscription. A parked `next()` resumes with "subscription closed". A second call does nothing. Destroying a `Subscription` does not send `UNSUB`.

## Messages

Doxygen: [`Message`](/doxygen/struct_async_nats_1_1_message.html) and [`Route`](/doxygen/struct_async_nats_1_1_route.html).

### `Message`

```cpp
struct Message {
  std::string subject;
  std::string payload;
  std::optional<std::string> reply;
};
```

One inbound NATS message. `reply` is set when the publisher supplied a reply subject.

### `MessageHandler`

```cpp
using MessageHandler = std::function<boost::cobalt::task<void>(Message)>;
```

Coroutine started for each message on a route subscription. The read loop starts it on the worker pool and does not wait. A slow handler does not stall the socket. Client calls from the handler return to the IO thread before they touch the socket. A thrown exception is logged and the connection stays up.

### `Route`

```cpp
struct Route {
  std::string subject;
  MessageHandler handler;
};
```

The subject and the handler that receives its messages. Passed to `Client::subscribe(vector<Route>)`.

## Errors

Doxygen: [`Error`](/doxygen/class_async_nats_1_1_error.html).

### `Error::Error`

```cpp
explicit Error(std::string message, ErrorKind kind = ErrorKind::other);
```

Failure thrown by the client and passed to `onError`. `what()` returns `message`. `kind` defaults to `ErrorKind::other`.

### `Error::kind`

```cpp
auto kind() const noexcept -> ErrorKind;
```

Which path produced this error.

### `ErrorKind`

| Enumerator | Meaning |
| --- | --- |
| `unreachable` | Resolve or the TCP connect failed. |
| `interrupted` | The socket died, the peer sent EOF, or the handshake failed. |
| `closed` | `Client::close()` finished the connection. |
| `signal` | The process received `SIGINT` or `SIGTERM`. |
| `other` | A protocol `-ERR`, or a programming mistake such as a missing client. |

## Runtime

Doxygen: [`Core`](/doxygen/class_async_nats_1_1_core.html) and [`Core.h`](/doxygen/_core_8h.html).

`Core` is a process-wide singleton. Socket operations are not thread-safe and are not run on the worker pool.

### `Core::instance`

```cpp
static auto instance() -> Core&;
```

The process-wide runtime. Constructed on the first call.

### `Core::ioThreads`

```cpp
auto ioThreads() const -> std::size_t;
```

Always 1. Socket IO runs on that thread.

### `Core::workerThreads`

```cpp
auto workerThreads() const -> std::size_t;
```

Number of threads in the worker pool. `NATS_EVENT_LOOP_WORKER_THREADS` sets it and defaults to 1. Empty, zero, negative, and non-numeric values become 1. The pool accepts at most twice the hardware concurrency, and at least 2. A larger value is clamped.

### `Core::threadPool`

```cpp
auto threadPool() -> boost::asio::thread_pool&;
```

Pool for blocking work posted with `boost::asio::post`. Do not run NATS socket operations on this pool.

### `Core::ioContext`

```cpp
auto ioContext() -> boost::asio::io_context&;
```

Private. The `io_context` the IO thread is running. `EventLoop` is the only caller.

### `Core::release`

```cpp
void release();
```

Private. Stop the IO context so its `run()` can return. `EventLoop` calls this when `co_main` finishes.

### `Core::join`

```cpp
void join();
```

Private. Join the IO thread after `release()`.

## JetStream

Doxygen: [`jetstream`](/doxygen/namespace_async_nats_1_1jetstream.html), [`Context`](/doxygen/class_async_nats_1_1jetstream_1_1_context.html), [`kv::Store`](/doxygen/class_async_nats_1_1jetstream_1_1kv_1_1_store.html), and [`ObjectStore::Store`](/doxygen/class_async_nats_1_1jetstream_1_1_object_store_1_1_store.html).

`jetstream::make` returns a context that shares the client's connection. Copies of `Context` share that connection. An lvalue client passed to `make` is copied and stays usable.

### `jetstream::make`

```cpp
auto make(Client client) -> boost::cobalt::task<Context>;
```

JetStream context for `client`. The argument is taken by value.

### `Context::createKeyValue`

```cpp
auto createKeyValue(kv::Config config) -> boost::cobalt::task<kv::Store>;
```

Create the key-value bucket and return a handle. Throws when the bucket name is invalid, `history` is above 64, or the server rejects the stream.

### `Context::getKeyValue`

```cpp
auto getKeyValue(std::string bucket) -> boost::cobalt::task<kv::Store>;
```

Open an existing key-value bucket. Throws when the name is invalid or the bucket does not exist.

### `Context::createObjectStore`

```cpp
auto createObjectStore(ObjectStore::Config config) -> boost::cobalt::task<ObjectStore::Store>;
```

Create the object-store bucket and return a handle. Throws when the bucket name is invalid or the server rejects the stream.

### `Context::getObjectStore`

```cpp
auto getObjectStore(std::string bucket) -> boost::cobalt::task<ObjectStore::Store>;
```

Open an existing object-store bucket. Throws when the name is invalid or the bucket does not exist.

### `kv::Config`

```cpp
struct Config {
  std::string bucket;
  std::int64_t history = 1;
};
```

Settings for a new key-value bucket. `history` is the number of revisions kept per key. It is clamped to at least 1. A value above 64 throws.

### `kv::Entry`

```cpp
struct Entry {
  std::string key;
  std::string value;
  std::uint64_t revision = 0;
};
```

One stored key, its value, and the stream sequence of that value.

### `kv::Store::put`

```cpp
auto put(std::string key, std::string value) -> boost::cobalt::task<std::uint64_t>;
```

Write `value` at `key`. Returns the stream sequence of the new value.

### `kv::Store::create`

```cpp
auto create(std::string key, std::string value) -> boost::cobalt::task<std::uint64_t>;
```

Write `value` only when `key` is absent or already deleted. Returns the stream sequence. Throws when the key already holds a value.

### `kv::Store::update`

```cpp
auto update(std::string key, std::string value, std::uint64_t revision)
    -> boost::cobalt::task<std::uint64_t>;
```

Replace `key` when `revision` is still the latest sequence. Returns the stream sequence of the new value. Throws when the revision does not match.

### `kv::Store::get`

```cpp
auto get(std::string key) -> boost::cobalt::task<std::optional<std::string>>;
```

The current value of `key`, or `std::nullopt` when the key is missing or deleted.

### `kv::Store::entry`

```cpp
auto entry(std::string key) -> boost::cobalt::task<std::optional<Entry>>;
```

The current value and revision of `key`, or `std::nullopt` when the key is missing or deleted.

### `kv::Store::remove`

```cpp
auto remove(std::string key) -> boost::cobalt::task<void>;
```

Publish a delete marker. Older revisions stay in the stream.

### `kv::Store::purge`

```cpp
auto purge(std::string key) -> boost::cobalt::task<void>;
```

Publish a purge marker and drop the history of `key`.

### `ObjectStore::Config`

```cpp
struct Config {
  std::string bucket;
};
```

Settings for a new object-store bucket.

### `ObjectInfo`

```cpp
struct ObjectInfo {
  std::string name;
  std::uint64_t size = 0;
  std::uint64_t chunks = 0;
};
```

Name, size, and chunk count of a stored object.

### `ObjectStore::Store::put`

```cpp
auto put(std::string name, std::string data) -> boost::cobalt::task<ObjectInfo>;
```

Store `data` under `name`, replacing a previous object of that name. The bytes are split into chunks. Returns the name, size, and chunk count.

### `ObjectStore::Store::get`

```cpp
auto get(std::string name) -> boost::cobalt::task<std::string>;
```

The bytes stored under `name`. Throws when the object does not exist.

### `ObjectStore::Store::info`

```cpp
auto info(std::string name) -> boost::cobalt::task<ObjectInfo>;
```

Name, size, and chunk count of `name`. Throws when the object does not exist.

### `ObjectStore::Store::remove`

```cpp
auto remove(std::string name) -> boost::cobalt::task<void>;
```

Mark `name` deleted and purge its chunks. Throws when the object does not exist.

## Internal

Doxygen: [`EventLoop`](/doxygen/class_async_nats_1_1_event_loop.html), [`Session.h`](/doxygen/_session_8h.html), and [`ThreadCount.h`](/doxygen/_thread_count_8h.html).

These functions are not installed. They live in `<AsyncNats/client/Session.h>`, `<AsyncNats/eventloop/EventLoop.h>`, and `<AsyncNats/core/ThreadCount.h>`.

### `EventLoop::setup`

```cpp
void setup();
```

Start the IO thread and the worker pool. A second call does nothing. This constructs `Core::instance()`.

### `EventLoop::run`

```cpp
auto run(int argc, char** argv) -> int;
```

Arm `SIGINT` and `SIGTERM`, spawn `watchSignals`, and spawn `co_main`. Returns 0. The integer `co_main` returns is only logged.

### `parseThreadCount`

```cpp
auto parseThreadCount(const char* text) -> std::size_t;
```

Parse `NATS_EVENT_LOOP_WORKER_THREADS`. Empty, zero, negative, and non-numeric text become 1. A value above `maxThreadCount()` is clamped to that limit.

### `maxThreadCount`

```cpp
auto maxThreadCount() -> std::size_t;
```

Twice the hardware concurrency, and at least 2.

### `reportError`

```cpp
auto reportError(const Error& failure) -> boost::cobalt::task<void>;
```

Log `failure` and run `onError`. Kind `closed` is not logged and does not run the handler. Kind `signal` is logged at info. A handler already on the stack is not entered again.

### `closeAllClients`

```cpp
auto closeAllClients(const Error& failure) -> boost::cobalt::task<void>;
```

Close every tracked client with `failure`, which wakes parked `closed()` and `next()` calls.

### `requestStop`

```cpp
void requestStop();
```

Set the process-wide stop flag. A `connect` still in progress, and a later `connect`, throw kind `signal`.

### `stopRequested`

```cpp
auto stopRequested() -> bool;
```

Whether `requestStop` has run.
